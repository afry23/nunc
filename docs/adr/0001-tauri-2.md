# ADR 0001 – Tauri 2 als Plattform

- Status: akzeptiert
- Datum: 2026-10-03

## Kontext

Die Go-App `nunc-go` nutzt Wails v3 (alpha) mit Svelte 3 und läuft nur auf Desktop. Ziel ist eine App für macOS,
Windows, Linux, Android und iOS mit gemeinsamer Fachlogik und möglichst wenig plattformspezifischem Code.

## Entscheidung

Neuschreibung als **Tauri 2** mit Rust-Backend und React-19/TypeScript-Frontend (Vite).

- Eine Codebasis für Desktop und Mobile (`tauri android init`, `tauri ios init`).
- Rust-Backend erlaubt eine pure, plattformfreie Domänenschicht (`nunc-core`) und gemeinsame Crates für Store/Sync.
- Offizielle Plugins für Notifications, Dialoge, Dateizugriff, Single-Instance, OS-Erkennung.
- Plattformcode über `#[cfg(desktop)]`/`#[cfg(mobile)]` und getrennte Capabilities
  (`src-tauri/capabilities/desktop.json`, `mobile.json`).

Alternativen: Flutter/React Native (Neuschreibung der UI in anderer Welt, kein Rust-Kern), Wails (kein Mobile),
reine PWA (keine zuverlässigen Hintergrund-Notifications).

## Konsequenzen

- Mobile-Betriebssysteme suspendieren die App → Timer-Modell mit Zeitstempeln (ADR 0004).
- Tauri-Mobile ist jünger als Desktop; Plugins haben Lücken (ADR 0004: iOS-Datumsfehler im Notification-Plugin).
- Das Webview unterscheidet sich je Plattform (WKWebView, Android WebView, WebView2, WebKitGTK): UI auf allen
  Zielplattformen testen, keine `.ogg`-Sounds auf iOS (→ `.mp3`).
- Der Desktop-E2E-Test über `tauri-driver` ist auf macOS nicht verfügbar (nur Linux/Windows-CI).
- Der Datenpfad folgt dem Bundle-Identifier (`com.afry.nunc`) und weicht vom Go-Pfad ab → Übernahme der
  vorhandenen DB beim ersten Start (Ticket M2-07).
